## はじめに

### 本ツールの目的

規程レビューツールは、社内規程文書の品質を自動的にチェックするシステムです。マルチクラウドLLM（Azure AI Foundry / AWS Bedrock / GCP Vertex AI / Ollama）とマルチOCR（Azure Document Intelligence / Tesseract）に対応しています。AIが以下の観点から文書を分析し、改善すべき箇所を指摘します：

- **用語の統一性**: 社内用語辞書との整合性
- **表現の明確性**: 曖昧な表現の検出
- **責任主体の明確化**: 誰が何をするかの明確性
- **法令・規程参照の正確性**: 参照先の妥当性
- **実務適合性**: 実際に運用可能かの検証

### 対象ユーザー

- 規程管理担当者
- 法務・コンプライアンス部門
- 内部監査部門
- 文書作成・レビュー担当者

## マスタデータ管理

### 用語辞書

社内で統一して使用すべき用語を登録します。

#### 登録手順

1. サイドバーから「用語辞書」をクリック
2. 「新規登録」ボタンをクリック
3. 以下の情報を入力：

| 項目 | 説明 | 例 |
|-----|------|-----|
| 用語 | 正式な用語名 | 従業員 |
| 別名 | 同義語・類語（カンマ区切り） | 社員, スタッフ |
| 定義 | 用語の正確な定義 | 当社と雇用契約を締結している者 |
| カテゴリ | 分類 | 人事, IT, 法務, 財務 等 |
| 使用上の注意 | 使用時の注意点 | 「社員」ではなく「従業員」を使用 |

4. 「保存」をクリック

#### 用語検索

- 検索ボックスにキーワードを入力
- ベクトル検索により類似した用語も表示されます

### チェック項目

AIがレビュー時に確認する観点を設定します。

| カテゴリ | 説明 |
|---------|------|
| TERMINOLOGY | 用語の統一性チェック |
| GRAMMAR | 文法・曖昧表現チェック |
| STRUCTURE | 文書構造チェック |
| COMPLIANCE | 法令準拠チェック |
| CONSISTENCY | 整合性チェック |
| SECURITY | セキュリティ要件チェック |
| OPERATIONAL | 実務適合性チェック |

#### 重要度設定

- **HIGH**: 必ず対応が必要
- **MEDIUM**: 対応を推奨
- **LOW**: 参考情報

### 記載ルール

文書の記載フォーマットルールを登録します。

| タイプ | 説明 | 例 |
|-------|------|-----|
| STYLE | 文体ルール | 文末は「である」調で統一 |
| FORMAT | フォーマットルール | 日付は西暦4桁で表記 |
| TERMINOLOGY | 用語ルール | 外来語はカタカナ表記 |

## 文書のアップロード

### 対応ファイル形式

- PDF（推奨）
- 最大ファイルサイズ: 50MB

### アップロード手順

1. サイドバーから「文書管理」をクリック
2. 「アップロード」ボタンをクリック
3. ファイルを選択またはドラッグ＆ドロップ
4. アップロード完了を待つ

### OCR処理

アップロード後、設定されたOCRプロバイダーで自動的にテキスト抽出が実行されます：

| OCRプロバイダー | 説明 |
|---------------|------|
| Azure Document Intelligence | 高精度クラウドOCR（推奨） |
| Tesseract（ローカル） | 無料のローカルOCR |
| AWS Tesseract（リモート） | AWS上のTesseract REST API |

- 処理状況: 「処理中」→「完了」
- 処理時間: ファイルサイズにより異なる（目安: 1ページあたり数秒）
- テキスト埋め込みPDFの場合、OCRなしでもPyPDF2による抽出が可能です

## レビューの実行

### レビュー開始

1. 文書管理ページで対象文書の「レビュー実行」をクリック
2. または、レビュー一覧ページから「新規レビュー」をクリック
3. チェック項目を選択（デフォルトは全項目選択）
4. 「実行」をクリック

### レビュー進行状況

```
[処理中] ████████████░░░░░░░░ 60%
チェック中: 責任主体明確化チェック (4/7)
```

### 処理時間の目安

| 文書ページ数 | 処理時間目安 |
|------------|------------|
| 1-5ページ | 1-2分 |
| 5-20ページ | 2-5分 |
| 20ページ以上 | 5分以上 |

```
│ HIGH: 3件  MEDIUM: 8件  LOW: 4件                  │
├────────────────────────────────────────────────────┤

├────────────────────────────────────────────────────┤
│                                                    │
│ ┌──────────────────────────────────────────────┐ │
│ │ [HIGH] 用語統一チェック        第2条         │ │

│ │ 問題内容: 「従業員」との表記ゆれがあります    │ │
│ │ 改善提案: 「社員」→「従業員」に統一          │ │
│ │                                              │ │
│ │ [承認] [保留] [却下]                         │ │
│ └──────────────────────────────────────────────┘ │
│                                                    │
└────────────────────────────────────────────────────┘
```

### 指摘事項の構成

| 項目 | 説明 |
|-----|------|
| 重要度 | HIGH / MEDIUM / LOW |
| チェック項目 | どの観点でのチェックか |
| 該当箇所 | 条文番号や位置情報 |
| 問題箇所 | 問題のある原文 |
| 問題内容 | 何が問題かの説明 |
| 改善提案 | 具体的な修正案 |

### 対応アクション

| アクション | 説明 | 用途 |
|-----------|------|------|
| 承認 | 指摘を受け入れ修正する | 妥当な指摘の場合 |
| 保留 | 後で対応を検討する | 判断を保留する場合 |
| 却下 | 指摘を採用しない | 意図的な記載の場合 |

### 一括処理

複数の指摘を一括で処理する場合：

1. 対象の指摘にチェックを入れる
2. 「未対応をすべて選択」で一括選択可能
3. 「一括承認」ボタンをクリック

### フィルタリング

- **重要度別**: HIGH / MEDIUM / LOW
- **ステータス別**: 未対応 / 承認 / 却下 / 保留

## よくある質問

### Q: レビューに時間がかかる

**A**: 以下を確認してください：
- 文書のページ数が多い場合は時間がかかります
- ネットワーク接続を確認してください
- LLMプロバイダーのレート制限に達している可能性があります
- ローカルLLM（Ollama）使用時はマシンスペックに依存します

### Q: OCRの精度が低い

**A**: 以下をお試しください：
- 元のPDFの品質を確認（スキャン品質、解像度）
- テキスト埋め込みPDFを使用
- 手書き文字は認識精度が下がります
- 高精度が必要な場合はAzure Document Intelligenceの使用を推奨します
- Tesseract使用時は言語パック（`TESSERACT_LANG=jpn+eng`）の設定を確認してください

### Q: 指摘が多すぎる

**A**: 以下で調整できます：
- 重要度でフィルタリングしてHIGHのみ表示
- チェック項目を絞ってレビューを実行
- マスタデータ（用語辞書等）を調整

### Q: 誤った指摘が多い

**A**: 以下をご検討ください：
- 用語辞書に正式な表記を登録
- 記載ルールを実情に合わせて更新
- 意図的な例外は「却下」として記録

### Q: 同じ指摘が繰り返し出る

**A**:
- 用語辞書に正式な用語と別名を正しく登録してください
- 頻出するパターンは記載ルールに追加検討

## 操作のヒント

### 効率的なレビューのコツ

1. **初回レビュー**: 全チェック項目で実施し、傾向を把握
2. **重点チェック**: HIGHの指摘を優先対応
3. **マスタ更新**: 頻出パターンは用語辞書に追加
4. **定期レビュー**: 規程改訂時には必ずレビューを実施
