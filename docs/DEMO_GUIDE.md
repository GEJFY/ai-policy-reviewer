## 環境準備

### 必要条件
- Python 3.11+ / Node.js 20+ がインストール済み（またはDocker Desktop）
- LLMプロバイダーのいずれかが設定されていること（Azure / AWS Bedrock / GCP Vertex AI / Ollama）
- ポート 3030（フロントエンド）、8080（バックエンド）が空いていること

### 一括セットアップ（推奨）

```bash
# demo_setup.bat をダブルクリックするだけで以下が実行されます:
# 1. デモデータ投入（用語辞書50件、チェック項目20件、記載ルール15件）
# 2. サンプルPDF生成（就業規則、情報セキュリティ、内部統制の3文書）
# 3. バックエンド・フロントエンド起動
demo_setup.bat
```

### 手動セットアップ

```bash
# 1. 環境変数の設定（初回のみ）
cp .env.example .env
# .env ファイルを編集してLLMプロバイダーの認証情報を設定

# 2. デモデータの投入
cd backend
python -m scripts.seed_demo_data

# 3. サンプルPDFの生成
python -m scripts.generate_demo_pdfs

# 4. サービス起動
cd ..
start_all.bat
# または手動で:
#   バックエンド: cd backend && uvicorn app.main:app --reload --port 8080
#   フロントエンド: cd frontend && npm run dev
```

### 確認URL
- フロントエンド: http://localhost:3030
- バックエンドAPI: http://localhost:8080
- API仕様書: http://localhost:8080/docs

### 情報セキュリティポリシーの特徴

12章44条の本格的な情報セキュリティポリシーです。

**含まれるテーマ**:
- 組織体制（CISO、情報セキュリティ委員会、情報管理責任者）
- 情報資産の4段階分類（極秘/秘密/社外秘/公開）と取扱いルール
- アクセス管理（最小権限、多要素認証、特権アカウント管理）
- 物理的セキュリティ（セキュリティ区域、入退室管理、クリアデスク）
- 技術的対策（マルウェア、ネットワーク、暗号化、バックアップ）
- インシデント対応（CSIRT体制、4段階の重大度分類、対応手順）
- リモートワーク・BYOD対応
- 委託先管理、教育・訓練、監査

### 内部統制規程の特徴

10章42条の会社法・J-SOX対応の内部統制規程です。

**含まれるテーマ**:
- 内部統制の6要素（統制環境、リスク評価、統制活動、情報と伝達、モニタリング、ITへの対応）
- 組織体制（取締役会、内部統制委員会、内部監査部門、三様監査）
- リスク評価（影響度×発生可能性マトリクス、リスク対応4分類）
- 統制活動（職務分離、決裁権限5段階、文書化、IT統制）
- J-SOX対応（全社的統制、業務プロセス統制、IT統制の評価）
- 不備の3段階分類（重要な欠陥/重要な不備/軽微な不備）
- 子会社管理

## デモシナリオ

### シナリオ概要

**背景設定**:
株式会社サンプル商事（従業員500名、東証スタンダード上場）は、年次の社内規程見直しを実施しています。今回、人事部から「就業規則」の改定案（第3版）が提出され、法務部がAIを活用したレビューを初めて実施します。

**登場人物**:
- 山田太郎（法務部 規程管理担当）——AIレビューツールのオペレーター
- 鈴木部長（法務部長）——レビュー結果の最終確認者
- システム：AI規程レビューツール

**ストーリー**:

> 「山田さん、人事部から就業規則の改定案が届きました。今回からAIレビューツールを使って
> 事前チェックをお願いします。特に、前回の改定で指摘された用語の不統一が解消されているか
> 確認してください」と鈴木部長。
>
> 山田は改定案PDFをツールにアップロードし、全20項目のチェックを実行する。
> AIが数分で16件の指摘を検出。用語混在、文体不統一、法的要件の漏れなど。
> 山田は各指摘を確認し、承認/却下の判断を行い、レビュー報告書を出力する。

**デモの目的**:
1. マスタデータ（用語辞書50件・チェック項目20件・記載ルール15件）の確認
2. 改定案PDFのアップロードとOCR処理
3. AIによる7カテゴリ20項目の自動レビュー実行
4. 指摘事項の確認・承認・却下ワークフロー
5. レビュー報告書の出力

## 操作手順

### Phase 1: マスタデータの確認（5分）

#### 1.1 用語辞書の確認

1. サイドメニューから「用語辞書」をクリック
2. 登録済みの社内用語（50件）を確認
   - **人事** (15件): 従業員、正社員、契約社員、パートタイマー、嘱託社員、管理監督者、所定労働時間、時間外労働、年次有給休暇、休職、懲戒処分、解雇、退職、人事考課、賃金
   - **法務** (10件): 決裁権限、稟議、取締役会、代表取締役、利益相反取引、コンプライアンス、内部通報、個人情報、契約、守秘義務
   - **財務** (10件): 予算、決算、経費、仮払い、精算、売掛金、買掛金、固定資産、減価償却、税務調査
   - **IT** (8件): 情報システム、情報資産、アクセス権限、パスワード、ウイルス、バックアップ、インシデント、クラウドサービス
   - **一般** (7件): 当社、本規程、別途定める、遅滞なく、所属長、事業年度、施行
3. 検索機能で「従業員」を検索
4. 用語の詳細を確認：定義、カテゴリ、同義語（「社員」「スタッフ」「職員」）、使用上の注意

**デモポイント**:
> 「例えば『従業員』という用語には、同義語として『社員』『スタッフ』が登録されています。
> 規程内でこれらの表記ゆれがあった場合、AIが自動的に検出して指摘します」

#### 1.2 チェック項目の確認

1. サイドメニューから「チェック項目」をクリック
2. 7カテゴリ・20項目のチェック項目を確認
   - **TERMINOLOGY (3件)**: 社内用語の統一性、定義との整合性、曖昧表現の検出
   - **GRAMMAR (3件)**: 文体統一（である体）、受動態の過剰使用、一文の長さ
   - **STRUCTURE (3件)**: 条番号の連続性、項・号の形式、章・節構成の妥当性
   - **COMPLIANCE (3件)**: 労働基準法対応、個人情報保護法対応、ハラスメント防止義務
   - **CONSISTENCY (3件)**: 他規程との整合性、日付・期間の整合性、金額・数値の整合性
   - **SECURITY (2件)**: 機密情報取扱い、アクセス制御ルール
   - **OPERATIONAL (3件)**: 責任者の明確化、手続きの明確化、例外処理ルール
3. チェック項目の詳細を開き、重要度（HIGH/MEDIUM/LOW）とプロンプトテンプレートを確認

**デモポイント**:
> 「チェック項目は自由に追加・編集できます。御社固有のルールや、
> 過去の内部監査指摘事項なども登録可能です。各項目には重要度を設定でき、
> レビュー結果のフィルタリングに使えます」

#### 1.3 記載ルールの確認

1. サイドメニューから「記載ルール」をクリック
2. 15件の記載ルールを確認
   - **STYLE (4件)**: である体の使用、能動態の優先使用、二重否定の回避、一文一意の原則
   - **FORMAT (4件)**: 数字の半角統一、日付表記の統一（西暦）、金額表記の統一、条文参照の表記
   - **TERMINOLOGY (3件)**: 社内用語辞書との整合、「等」の使用制限、外来語の使用
   - **STRUCTURE (4件)**: 目的条項の配置、定義条項の配置、適用範囲の明記、附則の記載
3. 各ルールにはパターン（正規表現）、正しい形、悪い例・良い例が設定されていることを確認

---

### Phase 2: 文書アップロード（3分）

#### 2.1 PDFアップロード

1. サイドメニューから「文書管理」をクリック
2. 「新規アップロード」ボタンをクリック
3. `samples/就業規則_改定案_v2.pdf` を選択してアップロード
4. アップロード完了を確認（ステータスが「OCR処理中」→「完了」に変化）

**デモポイント**:
> 「PDFをアップロードすると、設定されたOCRプロバイダー（Azure Document Intelligence /
> Tesseract / AWS Tesseract）によるOCR処理が自動実行され、テキストが抽出されます。
> テキスト埋め込みPDFの場合はOCRなしでもPyPDF2で抽出可能です。
> 今回のサンプルはReportLabで生成されたテキスト埋め込みPDFなので、高精度に抽出できます」

#### 2.2 OCR結果の確認

1. アップロードした文書をクリック
2. 「プレビュー」タブでOCR結果を確認
3. 全61条+附則が正しく抽出されていることを確認

#### 2.3 追加文書のアップロード（オプション）

複数文書レビューを見せる場合:
1. `samples/情報セキュリティポリシー.pdf` もアップロード
2. `samples/内部統制規程.pdf` もアップロード
3. 複数文書の一覧管理ができることを確認

---

### Phase 3: AIレビュー実行（5分）

#### 3.1 レビュー設定

1. 就業規則の文書詳細画面で「レビュー実行」ボタンをクリック
2. チェック項目の選択画面が表示
3. 実行するチェック項目を選択（デモでは全20項目を選択）
   - ✅ 社内用語の統一性チェック
   - ✅ 定義との整合性チェック
   - ✅ 曖昧な表現の検出
   - ✅ 文体統一チェック（である体）
   - ✅ 受動態の過剰使用チェック
   - ✅ 条番号の連続性チェック
   - ✅ 労働基準法対応チェック
   - ✅ ハラスメント防止義務チェック
   - ✅ 日付・期間の整合性チェック
   - （他11項目も全選択）
4. 「レビュー開始」をクリック

**デモポイント**:
> 「チェック項目は目的に応じて選択できます。簡易チェックなら用語統一のみ、
> 正式レビューなら全項目を選択するなど、柔軟に対応できます。
> LLMプロバイダーの設定で精度重視（precision）/コスパ重視（cost_effective）も選べます」

#### 3.2 レビュー進捗の確認

1. 進捗バーでレビュー状況を確認
2. チャンクごとの処理状況を表示
3. 完了まで待機（通常1-3分程度、文書量とLLMプロバイダーにより変動）

---

### Phase 4: レビュー結果の確認（10分）

#### 4.1 指摘一覧の確認

1. レビュー完了後、「結果を見る」をクリック
2. 指摘事項の一覧を確認
   - 重要度（高・中・低）でフィルタ可能
   - カテゴリ（TERMINOLOGY/GRAMMAR/STRUCTURE/COMPLIANCE/CONSISTENCY/SECURITY/OPERATIONAL）でフィルタ可能

**期待される主な指摘**:

| # | 重要度 | カテゴリ | 指摘内容 |
|---|--------|----------|----------|
| 1 | 高 | TERMINOLOGY | 第1条・第3条・第42条: 「社員」→「従業員」に統一を推奨 |
| 2 | 高 | COMPLIANCE | 第13条: 時間外労働の上限（月45時間/年360時間）の明記が必要 |
| 3 | 中 | GRAMMAR | 第6条: 「採用します」→「採用する」（である体に統一） |
| 4 | 中 | GRAMMAR | 第31条: 「なりません」→「ならない」（である体に統一） |
| 5 | 中 | GRAMMAR | 第58条: 「なりません」→「ならない」（である体に統一） |
| 6 | 中 | TERMINOLOGY | 第16条: 「年休」→「年次有給休暇」（正式名称を使用） |
| 7 | 中 | CONSISTENCY | 第11条・第17条: 全角数字と半角数字が混在 |
| 8 | 中 | COMPLIANCE | 第57条: 70歳までの就業機会確保の努力義務に言及なし |
| 9 | 低 | CONSISTENCY | 附則: 「令和6年」→ 西暦表記または併記を推奨 |
| 10 | 低 | TERMINOLOGY | 第23条: 「等」の使用——具体的な列挙を推奨 |

#### 4.2 指摘詳細の確認

1. 指摘行をクリックして詳細を表示
2. 確認内容:
   - **該当箇所**: 原文テキスト（ハイライト付き）
   - **問題点の説明**: なぜ問題なのかの解説
   - **修正提案**: 具体的な修正文案
   - **参照チェック項目**: どのチェック項目に基づく指摘か
   - **参照用語**: 用語辞書のどの定義に基づくか（該当する場合）

**デモポイント**:
> 「AIが単に問題を指摘するだけでなく、具体的な修正案も提示します。
> また、どのチェック項目に基づく指摘かも明示されるので、判断の根拠が明確です。
> 例えば『社員→従業員』の指摘は、用語辞書の定義と照合した結果です」

#### 4.3 Before/After比較

1. 指摘詳細画面で「比較表示」タブをクリック
2. 原文と修正案を並べて表示
3. 差分がハイライトされることを確認

**具体例**:
```
【Before】 第3条（適用範囲）
この規程は、当社に勤務するすべての「社員」に適用する。

【After】 第3条（適用範囲）
この規程は、当社に勤務するすべての「従業員」に適用する。
```

---

### Phase 5: 承認ワークフロー（5分）

#### 5.1 個別承認・却下

1. 指摘一覧に戻る
2. **承認の例**: 用語統一の指摘（「社員→従業員」）を選択し「承認」
   - 承認理由: 「第2条の定義に合わせて統一」
3. **却下の例**: 文体の指摘を選択し「却下」
   - 却下理由: 「第6条は採用時の説明文書を兼ねるため、です・ます体を意図的に使用」
4. **保留の例**: 法的要件の指摘を選択し「保留」
   - 保留理由: 「顧問弁護士に確認後に判断する」

**デモポイント**:
> 「AIの指摘をそのまま採用するのではなく、人間が最終判断を行います。
> 意図的な表現や例外は却下することで、レビュー品質を担保します。
> 保留にした指摘は後から再度判断できるため、外部確認が必要な場合にも対応できます」

#### 5.2 一括承認

1. 複数の指摘をチェックボックスで選択
2. 「一括承認」ボタンをクリック
3. 確認ダイアログで「承認」を選択

#### 5.3 レビュー完了

1. 全ての指摘を処理
2. 「レビュー完了」ボタンをクリック
3. サマリー画面を確認:
   - 総指摘数: 16件
   - 承認: 10件
   - 却下: 3件（意図的な表現）
   - 保留: 3件（外部確認待ち）

---

### Phase 6: レポート出力（3分）

#### 6.1 レビューレポートの確認

1. 「レポート出力」ボタンをクリック
2. レポート内容を確認
   - レビュー概要（文書名、レビュー日、使用LLMモデル、チェック項目数）
   - カテゴリ別指摘集計（TERMINOLOGY: 4件、GRAMMAR: 3件、COMPLIANCE: 2件...）
   - 指摘事項一覧（承認済みのみ）
   - 統計情報（承認率、カテゴリ別分布）

#### 6.2 エクスポート

1. 「PDF出力」または「Excel出力」を選択
2. ファイルをダウンロード
3. 内容を確認

---

### Phase 7: 複数文書の比較レビュー（オプション・5分）

#### 7.1 情報セキュリティポリシーのレビュー

1. Phase 2.3でアップロード済みの情報セキュリティポリシーを選択

## よくある質問（デモ時）

### Q1: 既存の規程データベースと連携できますか？
> A: CSVインポート機能があり、既存データの一括登録が可能です。
> また、REST APIを通じた外部システム連携も対応可能です。

### Q2: チェック項目は自社でカスタマイズできますか？
> A: はい。チェック項目は自由に追加・編集できます。
> 業界固有の規制要件（金融業のFISC安全対策基準、医療業の個人情報ガイダンス等）や、
> 社内独自のルール、過去の監査指摘事項なども登録できます。

### Q3: AIの精度はどの程度ですか？
> A: 用語統一チェックは90%以上の精度を達成しています。
> LLMプロバイダーやモデルの選択で精度を調整できます。
> 法的要件チェックは参考情報としてご利用いただき、
> 最終判断は法務担当者が行う運用を推奨しています。

### Q4: オンプレミス環境でも利用できますか？
> A: Dockerコンテナで提供しているため、オンプレミス環境へのデプロイも可能です。
> Ollama（ローカルLLM）とTesseract（ローカルOCR）を使用すれば、
> クラウド接続なしで完全オンプレミス運用が可能です。
> 機密性の高い規程文書を社外に送信せずに処理できます。

### Q5: 処理時間はどの程度ですか？
> A: 10ページ程度の規程であれば、通常1-3分でレビューが完了します。
> 大規模な文書（50ページ以上）の場合は、チャンク分割により並列処理を行います。
> Ollama（ローカルLLM）を使用する場合は、モデルサイズとGPUの有無により変動します。

### Q6: どのLLMプロバイダーがおすすめですか？
> A: ユースケースにより異なります。
> - **高精度が必要な場合**: Azure GPT-5.2 または Claude Opus 4.6（precision ティア）
> - **バランス重視**: Claude Sonnet 4.5 または Gemini 3 Flash（balanced ティア）
> - **コスト重視**: Claude Haiku 4.5 または Nova Micro（cost_effective ティア）
> - **オフライン運用**: Ollama + qwen2.5:3b（無料、GPU推奨）

### Q7: 複数人で同時に使えますか？
> A: サーバーデプロイ構成では複数ユーザーの同時利用に対応しています。
> ローカル版は単一ユーザー利用を想定していますが、
> 同一ネットワーク内の他PCからのアクセスも可能です。

## トラブルシューティング

### 起動しない場合
```bash
# Docker使用時
docker-compose logs -f
docker-compose down && docker-compose up -d

# 手動起動時
# バックエンドのログを確認
cd backend && uvicorn app.main:app --reload --port 8080
# フロントエンドのログを確認
cd frontend && npm run dev
```

### APIエラーが発生する場合
1. `.env` ファイルのLLMプロバイダー設定を確認（`LLM_PROVIDER`と対応する認証情報）
2. APIキーの有効期限を確認
3. Rate Limitに達していないか確認
4. Ollama使用時は `ollama list` でモデルがインストール済みか確認

### OCRが動作しない場合
1. 設定されたOCRプロバイダーの設定を確認（`OCR_PROVIDER`環境変数）
   - Azure Document Intelligence: エンドポイントとAPIキー
   - Tesseract: `tesseract --version` でインストール確認、`TESSERACT_LANG=jpn+eng` 設定
   - AWS Tesseract: エンドポイントURLの疎通確認
2. 代替としてPyPDF2によるテキスト抽出が動作します（テキスト埋め込みPDFのみ）

### PDF生成でエラーが出る場合
1. ReportLabがインストールされているか確認: `pip install reportlab`
2. 日本語フォントが存在するか確認（Windows: `C:/Windows/Fonts/` 配下）
3. 手動でテキストファイルをPDFに変換することも可能
