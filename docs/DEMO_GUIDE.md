## 環境準備

### 必要条件
- Docker Desktop が起動していること
- Azure OpenAI のAPIキーが設定されていること
- ポート 3030（フロントエンド）、8080（バックエンド）が空いていること

### 起動手順

```bash
# 1. プロジェクトディレクトリに移動
cd ai-policy-reviewer

# 2. 環境変数の設定（初回のみ）
cp .env.example .env
# .env ファイルを編集してAzure OpenAI の情報を設定

# 3. サービス起動
docker-compose up -d

# 4. デモデータの投入
python backend/scripts/seed_demo_data.py
```

### 確認URL
- フロントエンド: http://localhost:3030
- バックエンドAPI: http://localhost:8080
- API仕様書: http://localhost:8080/docs

## デモシナリオ

### シナリオ概要

**背景設定**:
株式会社サンプル商事は、社内規程の改定作業を行っています。
人事部から「就業規則」の改定案が提出され、法務部がレビューを実施します。

**登場人物**:
- 山田太郎（法務部 規程管理担当）
- システム：AI規程レビューツール

**目的**:
1. マスタデータ（用語辞書・チェック項目）の確認
2. 改定案PDFのアップロードとOCR処理
3. AIによる自動レビュー実行
4. 指摘事項の確認と承認・却下

---

## 操作手順

### Phase 1: マスタデータの確認（5分）

#### 1.1 用語辞書の確認

1. サイドメニューから「用語辞書」をクリック
2. 登録済みの社内用語を確認
   - 「従業員」「正社員」「契約社員」などの人事関連用語
   - 「決裁権限」「稟議」などの承認関連用語
3. 検索機能で「従業員」を検索
4. 用語の詳細を確認（定義、カテゴリ、同義語）

**デモポイント**:
> 「このように、社内で使用される用語とその正式な定義を登録しておくことで、
> 規程内で統一された用語が使用されているかをAIがチェックできます」

#### 1.2 チェック項目の確認

1. サイドメニューから「チェック項目」をクリック
2. カテゴリ別のチェック項目を確認
   - 法的要件: 労働基準法対応など
   - 記載ルール: 文体統一、番号体系など
   - 用語統一: 社内用語の一貫性
3. チェック項目の詳細を開き、チェック観点を確認

**デモポイント**:
> 「チェック項目は自由に追加・編集できます。
> 御社固有のルールや、過去の監査指摘事項なども登録可能です」

#### 1.3 記載ルールの確認

1. サイドメニューから「記載ルール」をクリック
2. 文体、表記、フォーマットのルールを確認
   - 「である体」の使用
   - 数字の全角/半角統一
   - 年月日表記の統一

---

### Phase 2: 文書アップロード（3分）

#### 2.1 PDFアップロード

1. サイドメニューから「文書管理」をクリック
2. 「新規アップロード」ボタンをクリック
3. サンプルPDF「就業規則_改定案_v2.pdf」を選択
4. アップロード完了を確認

**デモポイント**:
> 「PDFをアップロードすると、Azure Document Intelligence による
> OCR処理が自動実行され、テキストが抽出されます」

#### 2.2 OCR結果の確認

1. アップロードした文書をクリック
2. 「プレビュー」タブでOCR結果を確認
3. テキストが正しく抽出されていることを確認

---

### Phase 3: AIレビュー実行（5分）

#### 3.1 レビュー設定

1. 文書詳細画面で「レビュー実行」ボタンをクリック
2. チェック項目の選択画面が表示
3. 実行するチェック項目を選択（デモでは全選択）
   - ✅ 用語統一チェック
   - ✅ 文体統一チェック
   - ✅ 法的要件チェック
   - ✅ 数値・日付整合性チェック
4. 「レビュー開始」をクリック

**デモポイント**:
> 「チェック項目は目的に応じて選択できます。
> 簡易チェックなら用語統一のみ、
> 正式レビューなら全項目を選択するなど、柔軟に対応できます」

#### 3.2 レビュー進捗の確認

1. 進捗バーでレビュー状況を確認
2. チャンクごとの処理状況を表示
3. 完了まで待機（通常1-3分程度）

---

### Phase 4: レビュー結果の確認（10分）

#### 4.1 指摘一覧の確認

1. レビュー完了後、「結果を見る」をクリック
2. 指摘事項の一覧を確認
   - 重要度（高・中・低）でフィルタ可能
   - カテゴリ（用語・文体・法的要件）でフィルタ可能

**指摘例**:
| 重要度 | カテゴリ | 指摘内容 |
|--------|----------|----------|
| 高 | 用語統一 | 「社員」と「従業員」が混在しています |
| 中 | 文体 | 第5条で「です・ます体」が使用されています |
| 低 | 表記 | 日付表記が「令和6年」と「2024年」で混在 |

#### 4.2 指摘詳細の確認

1. 指摘行をクリックして詳細を表示
2. 確認内容:
   - 該当箇所（原文テキスト）
   - 問題点の説明
   - 修正提案
   - 参照したチェック項目

**デモポイント**:
> 「AIが単に問題を指摘するだけでなく、
> 具体的な修正案も提示します。
> また、どのチェック項目に基づく指摘かも明示されます」

#### 4.3 Before/After比較

1. 指摘詳細画面で「比較表示」タブをクリック
2. 原文と修正案を並べて表示
3. 差分がハイライトされることを確認

---

### Phase 5: 承認ワークフロー（5分）

#### 5.1 個別承認・却下

1. 指摘一覧に戻る
2. 最初の指摘（用語統一）を選択
3. 「承認」ボタンをクリック
   - 承認理由を入力（任意）
4. 2番目の指摘（文体）を選択
5. 「却下」ボタンをクリック
   - 却下理由を入力「意図的な表現のため修正不要」

**デモポイント**:
> 「AIの指摘をそのまま採用するのではなく、
> 人間が最終判断を行います。
> 誤検知や意図的な例外は却下することで、
> AIの学習改善にも活用できます」

#### 5.2 一括承認

1. 複数の指摘をチェックボックスで選択
2. 「一括承認」ボタンをクリック
3. 確認ダイアログで「承認」を選択

#### 5.3 レビュー完了

1. 全ての指摘を処理
2. 「レビュー完了」ボタンをクリック
3. サマリー画面を確認
   - 総指摘数: 15件
   - 承認: 10件
   - 却下: 3件
   - 保留: 2件

---

### Phase 6: レポート出力（3分）

#### 6.1 レビューレポートの確認

1. 「レポート出力」ボタンをクリック
2. レポート内容を確認
   - レビュー概要
   - 指摘事項一覧（承認済みのみ）
   - 統計情報

#### 6.2 エクスポート

1. 「PDF出力」または「Excel出力」を選択
2. ファイルをダウンロード
3. 内容を確認

## よくある質問（デモ時）

### Q1: 既存の規程データベースと連携できますか？
> A: CSVインポート機能があり、既存データの一括登録が可能です。
> また、APIを通じた外部システム連携も対応可能です。

### Q2: チェック項目は自社でカスタマイズできますか？
> A: はい。チェック項目は自由に追加・編集できます。
> 業界固有の規制要件や、社内独自のルールも登録できます。

### Q3: AIの精度はどの程度ですか？
> A: 用語統一チェックは90%以上の精度を達成しています。
> 法的要件チェックは参考情報としてご利用いただき、
> 最終判断は法務担当者が行う運用を推奨しています。

### Q4: オンプレミス環境でも利用できますか？
> A: Dockerコンテナで提供しているため、
> オンプレミス環境へのデプロイも可能です。
> Azure OpenAI の代わりにローカルLLMを使用する構成も検討できます。

### Q5: 処理時間はどの程度ですか？
> A: 10ページ程度の規程であれば、通常1-3分でレビューが完了します。
> 大規模な文書（50ページ以上）の場合は、
> チャンク分割により並列処理を行います。

## トラブルシューティング

### 起動しない場合
```bash
# ログ確認
docker-compose logs -f

# 再起動
docker-compose down
docker-compose up -d
```

### APIエラーが発生する場合
1. .env ファイルのAzure OpenAI設定を確認
2. APIキーの有効期限を確認
3. Rate Limitに達していないか確認

### OCRが動作しない場合
1. Azure Document Intelligence の設定を確認
2. 代替としてPyPDF2によるテキスト抽出が動作します

## 付録: デモ用サンプルデータ

デモで使用するサンプルデータは `backend/scripts/seed_demo_data.py` で投入できます。

投入されるデータ:
- 用語辞書: 50件（人事・法務・一般カテゴリ）
- チェック項目: 20件（法的要件・記載ルール・用語統一）
- 記載ルール: 15件（文体・表記・フォーマット）
- サンプル文書: 3件（就業規則、情報セキュリティポリシー、内部統制規程）
